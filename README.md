# 케셰브 — 보안 Agent

ALEPH 방어전에서 직원 본인의 로그인 사용자·기기·세션 정보를 구분해 표시하는 보안 Agent 학습 프로젝트입니다. 제공 시작 틀 0.2.14를 기반으로 **13단계: 로그인 사용자·기기·세션 표시**를 구현했습니다. 이후 단계도 같은 프로젝트와 Git 기록을 유지하며 이어 갑니다.

## 13단계 구현 내용

| 영역 | 표시 내용 |
| --- | --- |
| 현재 사용자 | 사용자 이름과 ID |
| 현재 기기 | 기기 이름, ID, 보안 상태 |
| 현재 세션 | 세션 ID와 상태 |
| 기기 목록 | 각 기기의 이름, ID, 상태 |
| 세션 목록 | 각 세션의 ID와 상태 |

각 자료의 조회 상태를 독립적으로 처리합니다.

- `loading`: 불러오는 중
- `ok`: 전달받은 사용자·기기·세션 정보
- `error`: 연결 실패와 서버의 `error.message`
- 자료를 확인할 수 없으면 확인 불가 표시

모드는 `demo`일 때 **예제 자료**, `disconnected`일 때 **연결 없음**, `unknown`일 때 **확인 불가**로 표시합니다. 로딩·오류 상태에서도 모드 안내를 함께 표시합니다.

### 상태 표시 기준

| 구분 | API 상태값 | 화면 문구 |
| --- | --- | --- |
| 기기 | compliant | 보안 기준 충족 |
| 기기 | noncompliant | 보안 기준 미충족 |
| 기기 | unknown | 확인 불가 |
| 세션 | active | 활성 |
| 세션 | expired | 만료 |
| 세션 | revoked | 철회됨 |
| 세션 | unknown | 확인 불가 |

기기 보안 상태는 전달받은 상태를 표시하는 기능이며, 악성코드 검사나 치료 기능이 아닙니다.

## 구현 위치와 동작

수정한 학생 함수는 `student/extension.mjs`의 `renderIdentity`입니다.

```javascript
renderIdentity({ me, devices, sessions })
```

세 자료는 각각 `{ status, mode, data?, error? }` 형식으로 전달됩니다.

- `me.data`: `user`, `device`, `session`
- `devices.data`: 기기 배열
- `sessions.data`: 세션 배열

`document.createElement`와 `textContent`로 DOM 요소 하나를 반환합니다. 사용자 이름과 오류 메시지를 HTML로 해석하지 않습니다.

호출할 때마다 새 DOM을 생성하고 이전 응답을 보관하지 않습니다. 제공 UI가 반환된 DOM으로 학생 영역을 교체하므로 다시 불러온 결과를 표시할 수 있습니다. 오류 상태에서는 해당 자료의 이전 사용자·기기·세션 값을 출력하지 않습니다.

다른 학생 함수의 기본 문구, 제공 서버, `public/app.js`, 인증 설정은 유지했습니다. 보호 현황·업무 앱·보안 기록 메뉴와 다시 불러오기 버튼은 제공 UI를 사용합니다.

## 실행 방법

제공 시작 틀의 검수 환경은 **Node.js 24.19.0**이며 외부 npm 의존성이 없습니다. Git은 소스 버전 관리와 제출 커밋 확인에 사용합니다.

`package.json`이 있는 프로젝트 최상위 폴더에서 PowerShell을 열어 실행합니다.

### 기본 실행

```powershell
npm.cmd start
```

기존 서버·에이전트 연결을 확인합니다. 연결 어댑터가 준비되지 않았다면 연결 없음과 조회 실패가 표시됩니다.

### 예제 실행

```powershell
npm.cmd run demo
```

예제 사용자·기기·세션으로 화면을 확인합니다. 예제 자료는 실제 로그인 연결이나 실제 기기 보안 상태를 입증하지 않습니다.

### 브라우저 접속

서버 실행 후 다음 주소를 엽니다.

http://127.0.0.1:5189

서버 종료는 실행 중인 터미널에서 `Ctrl + C`를 누릅니다.

### 문법 검사

```powershell
npm.cmd run check
```

이 명령은 학생 모듈의 문법을 검사하며 실제 화면 동작이나 단계 통과를 판정하지 않습니다.

아래 항목은 작업 중 로컬 PC에서 직접 조작하고 화면 문구를 확인한 내용입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 세 메뉴를 마우스로 이동 | 확인 |
| 키보드로 메뉴 이동 및 Enter 조작 | 확인 |
| 연결되지 않은 상태에서 세 영역의 연결 없음·오류 메시지 표시 | 확인 |
| 예제 사용자 이름과 ID 표시 | 확인 |
| 예제 기기 이름·ID·확인 불가 상태 표시 | 확인 |
| 예제 세션 ID·활성 상태 표시 | 확인 |
| 예제 자료 안내 표시 | 확인 |
| 다시 불러오기 후 예제 정보 표시 | 확인 |
| 서버 종료 후 다시 불러오기 시 연결 실패 표시 | 확인 |
| 연결 실패 시 이전 예제 사용자·기기·세션 값 제거 | 확인 |

예제 데이터는 고정되어 있으므로 실제 브라우저에서 다른 사용자 값으로 바뀌는 과정까지 확인한 것은 아닙니다.

### 구현 작업 환경의 별도 점검

- 학생 모듈 JavaScript 문법 검사 완료
- 간이 DOM과 모의 입력을 이용한 73개 단언 검사 통과
- 각 자료의 로딩·오류 상태와 모드 안내 점검
- 기기·세션 상태별 한국어 문구 점검
- 다른 사용자 입력을 전달했을 때 새 DOM과 새 값 반환 점검
- 오류 입력에서 이전 사용자 정보가 출력되지 않는지 점검
- 제공 ZIP과 비교해 학생 모듈 이외의 기존 파일 변경 없음 확인

모의 DOM 검사는 실제 브라우저 검사가 아닙니다. 검사 스크립트는 작업 환경에서 실행했으며 저장소에는 포함하지 않았습니다. 저장소 업로드 준비 과정에서 `.gitignore`를 추가했습니다.

### 미확인 항목

- 실제 계정과 기존 서버·에이전트 연결
- 실제 계정 정보와 학생 영역의 값 대조
- 실제 브라우저에서 모든 기기·세션 상태값 표시
- 브라우저 너비 1280px 이상 조건의 명시적 확인
- 과제 서버의 13단계 최종 통과 판정

## 설정과 비밀정보 관리

실제 `.env`, `.env.*`, `node_modules`, 로그 파일은 Git 추적에서 제외하고 `.env.example`은 유지합니다. 토큰·비밀번호·API 키를 소스 코드나 README에 기록하지 않습니다.

이번 단계에서 실제 유료 AI 요청이나 보안 조치를 수행하지 않았습니다.
